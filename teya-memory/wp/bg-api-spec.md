## 1. Протокол авторизации и сетевой транспорт

### 1.1. Аутентификация
* **Endpoint:** `POST https://login.bgoperator.ru/auth`
* **Параметры тела запроса (form-urlencoded):**
  * `login` — логин агентства
  * `pwd` — пароль агентства
* **Механизм сессии (Cookies):**
  * Сервер возвращает набор кук: `A1`, `Z1`, `L`.
  * Все последующие запросы к сервисам экспорта (`export.bgoperator.ru`) обязаны передавать куки `A1`, `Z1`, `L`.
  * **Ротация `Z1`:** значение куки `Z1` обновляется на каждом последующем ответе сервера. Клиент (WordPress transient/curl handler) обязан сохранять свежее значение `Z1` из заголовка `Set-Cookie` для следующего вызова.
  * **Обработка 401 Unauthorized:** при получении HTTP-статуса `401` сессия считается устаревшей; клиент выполняет повторную аутентификацию на `https://login.bgoperator.ru/auth` и обновляет транзиент кук.

### 1.2. Сжатие данных и обязательные заголовки
* **Заголовок:** `Accept-Encoding: gzip`
* **Требование:** является строго обязательным для всех запросов к API.
* **Ошибка 406 Not Acceptable:** при отсутствии заголовка `Accept-Encoding: gzip` сервер возвращает HTTP `406`.
* **Transport:** HTTPS / HTTP с обязательной распаковкой gzip-потока на стороне PHP/cURL.

## 3. Формат подробных цен `partners?action=price` vs `action=minprice`

### 3.1. Запрос подробных цен
* **Базовый URL:**
  `http://export.bgoperator.ru/partners?action=price&tid=211&flt=<country_id>&flt2=100510324872&id_price=<id_price>&data=<DD.MM.YYYY>&xml=11`
* **Структура ответа:**
  ```json
  {
    "href0": "https://www.bgoperator.ru/zaya?prx=...",
    "cur": "USD",
    "prx": "104499999900000097",
    "entries": [
      {
        "tour_date": "15.12.2026",
        "aircompany": "АК Россия (группа Аэрофлот)",
        "id_price": "121110228775",
        "town": "Хургада / HURGHADA",
        "id_hotel": "102632927562",
        "id_ns": "104610790295",
        "room": "STANDARD ROOM WITH POOL VIEW HB",
        "duration": "6",
        "o_duration": "6",
        "quota": "9",
        "prices": [
          {
            "amount": "1062",
            "RUR": "95018",
            "concr": "0",
            "href2": "&otv=102510005340",
            "ag": "12+, 12+"
          }
        ]
      }
    ]
  }
  ```

### 3.2. Почему рубли берутся СТРОГО из поля `RUR` подробных цен, а не из `action=minprice`
1. **Точность и актуальность пересчета:** В `action=price` поле `prices[].RUR` вычисляется сервером туроператора в момент генерации прайса с учетом точного внутреннего курса туроператора на дату вылета и конкретного состава пакета (топливные сборы, трансферы, аэропортовые сборы).
2. **Агрегация vs Реальный пакет:** В `action=minprice` выводятся ориентировочные сводные цифры часто в валюте страны (`USD`/`EUR`), а если в рублях — то базовая минимальная цена «на 1 человека при 2-местном размещении» без учета обязательных надбавок конкретного рейса.
3. **Соответствие 38-ФЗ «О рекламе» и защите прав потребителей:** Публикация цены из поля `RUR` подробного прайса гарантирует, что турист видит реальную стоимость тура на двоих («2 взрослых»), подтверждаемую ссылкой бронирования туроператора (`href0 + href1 + href2`), с юридически корректным дисклеймером.

## 4. Исследование расчета ночей: поле `duration` vs фильтр `f7`

### 4.1. Анализ полей длительности в API
* `duration` — **полная длительность тура в ночах** (включая проживание и транзитные ночи в перелете).
* `o_duration` — длительность **основного проживания** в отеле (`main accommodation nights`).
* `b_duration`, `ab_duration` — ночи до основного проживания (например, стыковка / стоповер в Москве/Дубае).
* `a_duration`, `ba_duration` — ночи после основного проживания.
* Фильтр `f7` в запросе (`&f7=7&f7=10`) — фильтрует выдачу по количеству ночей.

### 4.2. Разбор кейса: «2 ночи в Египте за 83 тыс. ₽»
* **Что обнаружено в образце `price_EG.xml`:**
  * Запись с датой `15.12.2026`, отель Minamark Beach Resort, `duration: 2`, цена `83 297 RUR`.
  * В том же файле тот же отель на `6 ночей` стоит `95 018 RUR`.
* **Причина появления «2 ночи в Египте»:**
  1. Это так называемый «короткий срез рейса» или «рекламный сити-брейк / тестовый слот авиакомпании», где 80–90% стоимости тура составляет регулярный перелет (Уфа — Москва — Хургада и обратно), а проживание в отеле заложено всего на 2 ночи.
  2. Перелет со стыковкой туда и обратно «съедает» почти двое суток в пути, оставляя туристу фактически 1 день на море.
* **Правило валидации и отображения ночей для витрины агентства:**
  1. **Фильтрация P0 для пляжного отдыха:** Для пакетных пляжных направлений (Египет, Таиланд, Вьетнам, ОАЭ) отбрасывать аномально короткие туры (`duration < 3` или `duration < 5` для дальнемагистральных направлений), так как они не представляют потребительской ценности для семейного и пляжного отдыха из Уфы.
  2. **Отображение в карточке:** Выводить строго целочисленное значение ночей проживания `nights` (из `o_duration` или `duration`), формулируя «X ночей в отеле».

## 5. Правила фильтрации и валидации данных

Каждый элемент из потока API перед попаданием в витрину или фикстуры проходит строгий конвейер валидации:
1. **Проверка цены:** `price_rur > 0`, отсутствие `null`, `NaN` или нулевых значений.
2. **Проверка дат:** дата вылета (`tour_date` / `date`) валидного формата `DD.MM.YYYY` и не находится в прошлом относительно среза.
3. **Проверка состава туристов:** поле `ag` содержит `"12+, 12+"` или `"14-99, 14-99"` (стандартный расчет на 2 взрослых).
4. **Проверка стоп-сейлов:** `isstop` не содержит `avia_to`, `avia_from`, `hotel`.
5. **Проверка отеля и курорта:** обязательное наличие наименования отеля, категории звездности и курорта.
6. **Обязательный дисклеймер (38-ФЗ):** наличие текста `рассчитана по курсу туроператора на [дата_среза], итоговая стоимость фиксируется при бронировании`.
